## Integration alert (vendor, not an idea card)

**ChatARV: two risks to the current pull.** Checked against REcontrol code.

1. **Auth: resolved, low risk.** forVEX calls ChatARV with a fixed `Bearer CHATARV_KEY` and MCP protocol version `2024-11-05` (`recontrol:supabase/functions/chatarv-run-comps/index.ts`, lines 57, 70, 219, 235). ChatARV's metadata describes OAuth for assistants (https://www.chatarv.ai/.well-known/oauth-protected-resource). Correction (Paul, 2026-10-06): ChatARV's own setup page documents "Advanced: set up with an API key" using an `Authorization: Bearer` header, which is exactly what forVEX does. Key auth is a supported path. The older protocol version is the only remaining item worth a glance.
2. **Silent format changes.** `run_comps` switched from bare JSON to markdown with a fenced JSON block, unannounced. It broke parsing until REcontrol commit `82d3c15` ("parse ChatARV markdown pulls"). ChatARV has no public changelog, pricing or API docs to watch (`/changelog`, `/pricing` and `/docs` return the app shell).

Also seen: PropLab runs a ChatARV comparison page (https://proplab.app/chatarv-alternative). BatchOffers and DealCheck both build on RentCast data.

Question for Paul: since you may advise ChatARV, is it worth asking them for a changelog or a notice when tool output formats change? That is the risk that actually bit.

## Top 5 idea cards

### 1. Deadlines that follow amendments, with the source clause shown
- **Product / source / date seen:**
  - Nekst: https://help.nekst.com/en-us/article/see-it-work-create-your-first-transaction-from-a-contract-18q84ti/ and https://nekst.featurebase.app/changelog (2026-08-12 item), seen 2026-10-06
  - ListedKit: https://www.listedkit.com/resources/what-is-ai-transaction-coordinator
- **What changed / what it does:**
  - Nekst: after a contract upload, "every task linked to a contract date has already adjusted itself to match your contract". Each extracted value shows "the exact line Nekst AI used".
  - ListedKit, on amendments: "the affected dates update, and the tasks that no longer apply are flagged".
- **Underlying job:** never miss an option, inspection or closing date, including after an amendment moves it.
- **Cell:** Readvise > Operate > Documents and deadlines > Contract contingency date extraction (`rv.doc.deadline-extract`)
- **Do we have it:** partial.
  - Built: extraction (`recontrol:lib/mcp/memory/extractScan.ts`, which already captures a `source_clause`) and tasks (`recontrol:lib/mcp/memory/obligations.ts`, `readvise:supabase/migrations/20260921160000_readvise_tasks_source_document_obligation.sql`).
  - Gap 1: by design, re-extraction after an amendment leaves an existing live task "alone" so the list is not doubled (`obligations.ts` header). A moved closing date therefore does not move the task.
  - Gap 2: there is no deadline view, so obligations appear as ordinary tasks.
- **Chat access today:** read+write (`forvex_materialize_obligations`, `forvex_project_scan`)
- **App filter:** fits. The view goes in Readvise; the amendment logic stays in recontrol.
- **Payoff for CRG:** high. A missed option or close date costs earnest money or an assignment fee, and amendments that move closing are routine.
- **Rough effort:** M. A cheap first step is S: a read-only calendar feed of key dates (Nekst Key Dates: https://help.nekst.com/en-us/article/key-dates-track-and-complete-your-critical-deadlines-hbd7q8/).
- **Recommendation:** improve existing.
- **Open question for Paul:** when an amendment moves a date, should the task update itself, or land in staged actions for you to approve?

A `forvex-change-order` Claude skill exists outside the repos.
- **Chat access today:** n/a (not built)
- **App filter:** fits REbuild app glue. It is not an engine-contract change while it stays in execution.
- **Payoff for CRG:** high. Scope adds are where flip margin leaks, and today they go into an "unexpected" bucket with nothing counting against contingency.
- **Rough effort:** M
- **Recommendation:** improve existing (turn an unexpected-scope line into a change order).
- **Open question for Paul:** should a change order need an approval (you or a partner) before it hits the budget, or is logging enough?

- **App filter:** route the AI extraction to the MCP layer (recontrol, a write tool for expense lines). The ledger stays in REbuild. Not engine, not Deal.
- **Payoff for CRG:** high, for two reasons:

- **Rough effort:** M
- **Recommendation:** improve existing.

- **App filter:** fits Readvise. If SFR is used, the data comes in through the MCP layer.
- **Payoff for CRG:** high on wholesale deals, low on flips.
- **Rough effort:** M to rank from our own records. S to trial SFR's MCP beside forVEX in chat (free 1,000 credits per https://mcp.sfranalytics.com/).
